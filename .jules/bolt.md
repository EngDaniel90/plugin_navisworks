## 2024-11-20 - [Optimize COM API Object Initialization in Navisworks Simulation Loops]
**Learning:** Initializing COM objects within an iterative simulation loop (like a Navisworks collision detection step) creates significant and unnecessary marshalling overhead. Navisworks operations accessing `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection()` run with O(N) complexity for model collections and delay simulations considerably when called repeatedly. Furthermore, executing `TestsRunTest` inside loop iterations is extremely computationally expensive, so it is necessary to immediately exit nested loops upon collision detection to avoid redundant API overhead.
**Action:** When working with Navisworks COM components inside iterative simulations, always fetch and cache `ComApi.InwOpState10` and `ComApi.InwOpSelection` outside of simulation loops and pass them to manipulation methods to avoid O(N) performance hits per cycle. Additionally, always implement early exit strategies (e.g., `break` or `return`) the moment a collision is detected rather than looping through all tests unnecessarily.
