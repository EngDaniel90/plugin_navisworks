## 2024-05-28 - [Eliminating O(N) Marshalling and Artificial Thread Blocking in Navisworks API Loops]
**Learning:** Moving objects iteratively via the Navisworks COM API (`MoveItemsUsingCOM`) within a simulation loop incurs severe O(N) marshalling overhead if `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection` are called on every step. Furthermore, using hardcoded delays like `await Task.Delay(50)` severely throttles performance in tightly-coupled simulation routines.
**Action:** Extract and cache `ComApi.InwOpState10` and `ComApi.InwOpSelection` outside of simulation loops and pass them directly as parameters to execution methods. To ensure Navisworks view rendering and responsiveness without artificial delays, replace `await Task.Delay(ms)` with `await Task.Yield(); Application.DoEvents();`.
