## 2024-03-21 - Navisworks COM API Marshalling Overhead in Simulation Loops
**Learning:** Repetitive O(N) marshalling between .NET and COM API (specifically `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection`) inside high-frequency simulation loops creates a massive performance bottleneck. The overhead of regenerating identical COM selection structures for the exact same `.NET` model items at every simulation step dramatically reduces frame rate and collision testing throughput. Another bottleneck is hardcoded delays like `Task.Delay(50)` that pause the execution thread unnecessarily; replacing them with `Task.Yield()` and forcing view renders with `Application.DoEvents()` maximizes throughput.
**Action:** When performing iterative transformations on a static selection of items, always compute and cache the `InwOpState10` and `InwOpSelection` objects exactly once before the loop. Pass these pre-computed COM structures directly into transformation helpers. Never re-marshal immutable selections inside an animation or physics loop. Also, use `Task.Yield()` + `Application.DoEvents()` to maintain UI responsiveness and maximize iteration speed instead of hard-coded blocks.
