## 2024-05-24 - COM Interop Marshalling Bottleneck in Navisworks Loops
**Learning:** In Navisworks plugins using `Autodesk.Navisworks.Interop.ComApi`, calling `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection()` repeatedly inside high-frequency simulation loops incurs severe marshalling overhead (O(N) translation of .NET objects to COM). Additionally, continuing to execute `clashTestsData.TestsRunTest(test)` after a collision is found wastes tremendous CPU cycles since the simulation visually and practically only needs the *first* point of collision.
**Action:** Always cache `ComApiBridge.State` and the converted `InwOpSelection` outside of simulation loops and pass them to helper methods (like transform or reset methods). Always implement early exit (`break`) immediately upon detecting a valid collision to skip redundant expensive Navisworks API calls.
