## 2024-05-24 - [Navisworks UI Responsiveness vs API Overhead and Caching COM objects]
 **Learning:** In Navisworks API interactions, executing `TestsRunTest` is extremely computationally expensive. Hardcoded blocking delays like `Task.Delay(50)` do force view rendering, but limit maximum throughput. Furthermore, repetitive O(N) marshalling overhead from `.NET` to `COM` inside iteration loops should be cached in local variables outside the loop to avoid redundant overhead, as done in `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection`.
 **Action:** Instead of `Task.Delay(50)`, maximize UI throughput by combining `Task.Yield()` and `Application.DoEvents()`. Implement early exit in `TestsRunTest` results iterations and `while` loop, with `break` directly after finding a valid collision. Finally, cache `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection(items)` in variables before loops to circumvent redundant repetitive O(N) marshalling.
