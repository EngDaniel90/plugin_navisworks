## 2024-05-18 - Navisworks COM Iteration and Simulation Exit Optimization
**Learning:** In Navisworks plugins, properties like `doc.GetClash().TestsData` incur marshalling overhead if accessed inside a loop. Furthermore, COM interactions using `.NET` interop elements like `ComApiBridge.ToInwOpSelection` also incur massive O(N) penalties if initialized repeatedly. In terms of business logic, evaluating an entire simulation path after an active crash/clash is redundant and expensively executes `TestsRunTest`.
**Action:** Always pre-calculate invariant `.NET` / `COM` configurations (like state factories or item selections) outside descent/simulation loops. Break loops (`TestsRunTest` loops) immediately upon encountering valid logic collision points (`ClashResultStatus.Active` or `ClashResultStatus.New`) to reclaim execution time natively.
