## 2024-07-05 - Navisworks API Marshalling & Early Exits
**Learning:** In Navisworks collision detection loops, continuous interactions via COM API (like resolving internal states and converting item collections) cause O(N) marshalling overhead. Furthermore, executing `TestsRunTest` is extremely computationally expensive. Without early exits, simulations redundantly test already collided paths.
**Action:** Always cache `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection` prior to entering simulation loops to perform constant O(1) resolution. Additionally, enforce early exits (`break`) from validation and descent loops the moment a collision is detected to prevent costly `TestsRunTest` redundancies. Use `InvokeRequired` for WinForms updates when employing early loop exits in async functions to avert cross-thread violations.
