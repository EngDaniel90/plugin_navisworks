## 2024-03-24 - [Optimizing Navisworks COM Iteration and Clash Early Exit]
**Learning:** Repetitive marshalling of Navisworks COM objects (`ComApiBridge.State` and `ComApiBridge.ToInwOpSelection`) inside a highly iterative O(N) loop introduces huge performance overhead. Furthermore, executing the Navisworks clash engine is exceptionally costly and continuing to run tests on a `while` loop that descends position after a collision has already been detected is wasted work.
**Action:** Always cache COM objects (state and selection arrays) before entering iterative loops that modify view transforms. In addition, always implement early exit (`break;`) in both the nested validation loop and the outer transformation loop immediately after a collision is confirmed, bypassing redundant tests and geometry manipulation.
