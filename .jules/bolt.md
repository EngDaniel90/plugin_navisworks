## 2025-06-01 - Navisworks API COM Interop Overhead and Early Exit
**Learning:** In Navisworks plugins, repetitive marshalling of Navisworks core state and selection items (via COM API like `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection`) within heavy loops (like simulation steps) introduces massive O(N) performance overhead. Additionally, repeated clash tests (`TestsRunTest`) are computationally expensive, so checking results incrementally and breaking early out of test evaluations avoids redundant processing.
**Action:** Always cache COM bridged objects before entering simulation or manipulation loops. Pass the cached COM state/selection to helper methods (e.g., `MoveItemsUsingCOM`) rather than rebuilding them each frame. Implement early exits (`break`) in iteration and loop logic when the goal (e.g. finding a collision) is met to save expensive computations.
