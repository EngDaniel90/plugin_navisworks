## 2024-05-17 - [Optimizing Navisworks COM API Usage in Simulation Loops]
**Learning:** Instantiating COM objects like `ComApiBridge.State` and converting selections via `ComApiBridge.ToInwOpSelection()` inside a tight simulation loop creates significant O(N) marshalling overhead. Navisworks COM operations are computationally expensive and thread-affine, which severely degraded performance when repeatedly executed per iteration.
**Action:** When working with the Navisworks COM API in iterative processes (e.g., simulation loops), always cache the COM `InwOpState10` and `InwOpSelection` objects outside the loop and pass them as parameters to helper methods (like `MoveItemsUsingCOM` and `ResetItemsUsingCOM`) to avoid repetitive marshalling costs. Also, leverage `await Task.Yield(); Application.DoEvents();` to force geometry rendering without introducing blocking delays. Finally, always use early exits (`break`) when possible to avoid unneeded expensive API calls (e.g. `TestsRunTest`).
