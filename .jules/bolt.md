## 2024-05-15 - Navisworks COM API Marshalling & Yielding
**Learning:** In Navisworks plugins, recalculating `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection` inside a simulation loop causes heavy O(N) marshalling overhead. Also, hardcoded `Task.Delay` limits throughput, while `Task.Yield()` paired with `Application.DoEvents()` maximizes simulation speed while still keeping the UI responsive and forcing view rendering. Early exits in nested loops further optimize clash tests.
**Action:** Always cache `InwOpState10` and `InwOpSelection` outside of tight loops, pass them to helper methods, use `Task.Yield() + Application.DoEvents()` instead of arbitrary delays for UI/Rendering synchronization, and implement `break` statements to exit simulation loops immediately upon detecting a valid collision.
