## 2024-11-10 - O(N) Marshalling and Missing Early Exits in Navisworks Simulation Loops
**Learning:** In `LiftingForm.cs`, properties like `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection(items)` are re-evaluated in every iteration of the simulation loop via helper methods (`MoveItemsUsingCOM`, `ResetItemsUsingCOM`). This causes severe O(N) COM marshalling overhead. Furthermore, the `TestsRunTest` is extremely computationally expensive. The simulation loop lacked an early exit (`break`), causing it to continue running expensive clash tests and COM transitions even after a collision was already detected.
**Action:** When working with Navisworks COM interop inside loops, always extract and cache `ComApiBridge` state and selection objects before the loop. Pass them as parameters to helper methods. Implement early exit strategies (`break` or `return`) as soon as the target condition (e.g., a valid collision) is met to avoid redundant engine processing. Use pre-allocated delegates for UI updates to reduce GC pressure.
