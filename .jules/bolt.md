## 2024-06-25 - Optimization in Navisworks Simulation Loops
**Learning:** Repetitively accessing COM APIs (`ComApiBridge.State` and `ComApiBridge.ToInwOpSelection()`) within simulation loops (e.g., `RunSimulation` in Navisworks plugins) introduces significant O(N) marshalling overhead. Additionally, invoking Navisworks Clash Tests (`TestsRunTest`) is computationally expensive and shouldn't be repeatedly called after a collision has already been detected.
**Action:** When implementing iterative collision or physics loops in Navisworks plugins, ensure that all COM state and selection conversions are cached outside the main loop. Moreover, always implement an early exit (`break` or `return`) from the simulation loop immediately upon confirming a valid clash result to prevent redundant and expensive API calls.
