## 2024-06-06 - Navisworks COM API Caching and Loop Early Exit
**Learning:** In Navisworks plugins, `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection` trigger an expensive O(N) COM marshalling process. Performing this calculation repetitively inside a simulation loop severely impacts performance. Additionally, the `clashTestsData.TestsRunTest` is computationally heavy, and allowing the simulation loop to continue evaluating subsets of tests even after a collision has been successfully verified introduces massive redundant overhead.
**Action:** When creating repetitive visual overrides or collision checks via the Navisworks COM API, always cache the COM states `InwOpState10` and `InwOpSelection` outside the loop, passing them down into helper methods. For clash checks, implement early-exit strategies (e.g. `break` commands) inside the collision evaluation loops to terminate immediately after resolving a conclusive `New` or `Active` clash.
