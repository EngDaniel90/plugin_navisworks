## 2024-06-12 - COM Caching and Early Exits in Navisworks Simulation Loops
**Learning:** The Navisworks simulation loops (`TestsRunTest`) are highly sensitive to O(N) internal object allocations and API calls. Recreating COM objects (e.g., `ComApiBridge.State`, `ComApiBridge.ToInwOpSelection`) inside tight iteration loops imposes massive performance penalties due to marshalling overhead. Additionally, continuing to compute visual updates or check remaining clash heights after a collision has been flagged wastes cycles.
**Action:** When implementing loops that modify model item transforms or test for collisions, cache the COM selection state outside the loop and pass references instead. Implement strict early-exit strategies (`break`) upon detecting the first invalid clash condition to halt remaining computation.
