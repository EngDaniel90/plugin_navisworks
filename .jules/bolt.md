## 2024-05-24 - [Avoid O(N) COM Marshalling Overhead in Tight Navisworks Loops]
**Learning:** `ComApiBridge.State` and `ComApiBridge.ToInwOpSelection` operations translate .NET structures into Navisworks internal COM structures. Executing them inside a deep simulation loop effectively runs an O(N) translation on every positional update tick, completely crippling CPU performance on large models. Furthermore, checking clash test results doesn't require iterating over all children if a valid active collision has already been verified for that single check.
**Action:** Always pre-calculate and cache COM state and selection conversions outside of geometric simulation update loops. And whenever processing test results inside a loop, early exit the simulation iteration as soon as the first target condition (like collision detection) resolves to true.
